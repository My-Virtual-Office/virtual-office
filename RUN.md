# Virtual Office — run it

One command, on a machine with Docker:

```bash
docker compose up -d --build
```

First boot builds ~12 images and seeds the demo company. Give it 10–20 minutes and
a few GB of disk. After that, `docker compose up -d` starts in under a minute.

## Is it ready?

The seeder waits for the services it needs, so the honest signal is:

```bash
docker compose ps                 # everything healthy?
docker compose logs -f seed       # watch the demo data land
```

`seed` and `seed-history` are one-shot containers: they run, print, and exit 0.
That is success, not a crash.

## The `.env`

Generated by `make-release.sh` and included — compose cannot start without one,
which is why `docker compose up` alone is enough here.

- Database passwords are generated fresh for this machine. The volumes start
  empty, so they only have to agree with themselves.
- `COMPOSE_PROFILES=seed` is what pulls the seeder into a plain `up`. Remove it
  for an empty workspace.
- `OPENAI_API_KEY` drives the assistant, through an OpenAI-compatible endpoint
  (`OPENAI_BASE_URL` points at Groq). **Leave it blank and everything else still
  works** — ai-service starts and returns 503 on `/api/ai/chat`.
- `AGORA_*` drives voice/video.

**This file holds real credentials. Don't publish the zip.**

## Reaching it from another device

The browser URLs are baked into the bundles at build time. Put this machine's IP
in `PUBLIC_GATEWAY_URL` / `PUBLIC_COLYSEUS_WS` / `PUBLIC_ROOM_WS`, then rebuild:

```bash
docker compose up -d --build
```

One catch: browsers only allow the microphone on a secure origin. Over plain http
from a LAN IP the mic is blocked — chat, tasks and the 2D office are unaffected,
but voice needs localhost or https.

## Starting over

```bash
docker compose down -v      # -v also drops the databases, so the next up re-seeds
```
